还没有始终允许的应用

§3.2b 键

  1. bundleId
  2. exe / AUMID
  3. 规范化 appName

pid 不得单独作键。禁把 desktop_act:* 写入持久簿。

持久与覆盖

  • 跨会话 / 重启直至撤销；本机 only，禁云同步
  • 同 appKey 的 click / type / key 可跳普通 Dock
  • wait 免批（已有）
  • 始终允许只写 desktopAlwaysAllowAppKeys；本会话只写 conversationDesktopAllow

反例 · 禁止画出 / 禁止接线

  • 裸 desktop_act / 「任意桌面永久」进持久簿
  • 坐标 / allowForeground 因始终允许跳过
  • 敏感窗因始终允许跳过
  • Always-allow 跳过 CU-P1-R needs_second_confirm 并排卡
  • pid 当键；无稳 appKey 仍露出始终允许
  • 与「本会话」糊成一种；会话升持久 / 持久改会话表
  • 云同步名单 / Registry 策略 / Explore 注册 desktop_act
  • 第二套遥控器 · 脚注墙 · 空「已连接」假绿 · 行按钮写撕掉/移除/删除/Forget

给 mike / kai 的交接

mike · 名片与设置

  • 沿用 Permission Dock，不是新壳；四态齐全时突出「始终允许此应用」
  • 决策：allow / allow_session / allow_always / deny
  • testid：approval-allow · approval-session（今日代码或仍叫 approval-always，本会话 ≠ 持久，请改名）· approval-always-app · approval-deny
  • 无稳 appKey：隐藏始终允许；不要用 pid 凑一项
  • 设置嵌「电脑操控」卡：标题 / 含坐标前台敏感的说明 / 「撤销」/ 空态原文；撤销后列表立即更新
  • 勿画第二套遥控器、勿脚注墙、勿云同步开关

kai · 簿与闸

  • 持久键数组：desktopAlwaysAllowAppKeys（本机 prefs，不进 conversationDesktopAllow）
  • allow_always 只把该 appKey 写入持久簿
  • 「本会话允许此应用」只写会话表；不升簿
  • 设置「撤销」只从簿删该键；不管会话表（本会话仍由 CU-P1-S 管）
  • 命中顺序：desktopActAlwaysAsks（坐标/前台/敏感/二次确认）→ 会话表 → 持久簿
  • 禁持久 desktop_act:*；Explore 不注册；禁云策略
