Composer 铬条三件套不丢 · 图标 · 思考 · 探索/执行

Jojo 锁。同一 Composer 示意：左探索\|执行（C1 默认全引擎）、思考按能力、右引擎标 + 带图标模型芯片。对齐 explore-execute-p0.html 与 I1 换模成功脚注。设计已锁，不宣称应用 1:1。

锁 · 铬条 L→R（可 wrap，不可删）

  1. 探索 | 执行 — 每个有 Composer 的会话都在。默认 C1：宿主只读拦截写文件 / 磁盘 / 终端，不依赖 CLI 原生规划档。
  2. 思考 — 仅当 capabilities 声明 thinking / reasoning_effort。effort = 五档；model-id = 人话「思考 · 跟模型」；none = 不画（优于灰死）。
  3. 弹性空白 / 发送区
  4. 引擎 品牌标 — 点开既有 Picker / handoff，≠ I1
  5. 模型芯片 — I1 同引擎换模；芯片与名单行都带标（缺图 → 单字母色块，禁止空白）

I1 只换模型 id，不得拆模式与思考入口。脚注「同一助手，不换引擎」可留，不得挤掉分段。

验收

  1. Claude 等常用引擎会话：一眼能切探索/执行（C1）；图标在芯片与名单行上都在。
  2. 有 model-id / effort 思考能力时，有人话入口；换模后入口跟新模型刷新。
  3. 无思考能力：不画思考控件，探索\|执行仍在。
  4. C2 仅宿主拦不住写时：分段可见但禁用 +「此助手暂不支持探索/执行切换」，永不整段消失。
  5. I1 成功脚注不挤掉模式切换；名单无秃文字列。

重做整页 Composer · 把模式塞进 I1 菜单当隐藏项 · 无 capability 假思考 · ACP / 协议微标 · worktree / 新 runtime
