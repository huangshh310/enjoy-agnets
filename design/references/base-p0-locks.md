## BASE-P0-1 首启到第一句话

**一句话**：新用户装完、走完或跳过向导后，要么能说出第一句话，要么清楚知道还差哪一步、点哪里补。

### Do
1. **向导加「连一个模型」步**（放在「安装本机引擎」之后）。按真实检测给出选项：
   - 已就绪且可直接对话的外置引擎（如已登录的 Claude Code / Codex）→「用 {引擎} 对话」
   - 检测到本地模型服务（Ollama / LM Studio）→「用本机模型」
   - 「添加 API 密钥」→ 进入官方预设的添加表单，保存后回到向导这一步并显示已连上
   - 「以后再连」→ 允许跳过
2. **区分「引擎」和「模型」**：Enjoy 本地是引擎，没连模型就不能对话；向导和末屏不能把「引擎就绪」说成「可以开始」。
3. **末屏就绪语义诚实**：有至少一条可对话路线才写「可以开始了」；否则主文案「还差一步：连一个模型」+ 主按钮「去连接」，次按钮「先逛逛」。
4. **能回到向导**：设置 → 通用「重新打开入门向导」；设置搜索「向导 / 入门 / 引导」都能命中。
5. **没项目时说清楚**：主区空态写「选一个文件夹开始。Enjoy 只在你选的文件夹里读写。」+ 主按钮「选择文件夹」+ 可拖入；侧栏「新对话」在无项目时导航到这个空态，不直接弹系统窗口。用户亲手点「选择文件夹」才弹系统窗口（这是明确动作，允许）。
   - **已有项目时不出这个空态**：侧栏已列出项目，主区默认进入上次用过的项目（没有记录就进第一个），不再写「打开工作区」。
6. **无密钥发送用引导样式**：中性/提示色横幅「还差一步：连一个模型，才能发消息。草稿会留着。」+「去连接」；红色只留给真错误（密钥无效、网络失败、额度用完）。
7. 用户可见用词统一为「连接模型 / API 密钥」，不再出现「供应商密钥」。

### Don’t
- 没有可用路线时写「就绪 / 可以开始」
- 强制先填密钥才能看界面
- 自动在家目录建默认工作区或替用户选文件夹
- 不带说明直接弹系统选文件夹窗口
- 把密钥同步或上传到任何云端

### 验收 S1-1 … S1-7
| ID | 钉死句 |
|----|--------|
| S1-1 | 全新安装、无任何密钥/引擎登录：向导出现「连一个模型」步，四个选项按真实检测显示，不出现不可用的选项 |
| S1-2 | 在向导里加 API 密钥后回到向导，该步显示已连上；末屏「可以开始了」，首条消息能发出 |
| S1-3 | 选「以后再连」：末屏写「还差一步：连一个模型」，不写「可以开始」 |
| S1-4 | 设置里能重新打开向导；搜「向导」「入门」「引导」命中 |
| S1-5 | 无项目：主区有说明和「选择文件夹」；点侧栏「新对话」不直接弹系统窗口 |

| S1-7 | 侧栏已有项目时，启动后主区直接进入该项目，不出现「打开工作区」空态（亮/暗都验） |

## Luna 视觉说明（P0-1）

**布局。** 不换向导壳。仍是 `SetupGuideDialog` 约 800×540、`grid-rows-[auto_minmax(0,1fr)_auto]`、`GUIDE_INSET_CLASS` 左右 32px、底栏进度点 + 文本「跳过设置」+ 胶囊主钮（`GUIDE_BUTTON_CLASS` `h-9 rounded-full`）。步骤表在 `SETUP_GUIDE_FACE` 的 `engines` 之后插入 `connect-model`，序号改成「第 n 步，共 7 步」。中间步标题居左；介绍 / 完成仍 hero 居中。

**「连一个模型」步。** 选项是**可点行**，复用 `GUIDE_TILE_CLASS`（淡描边圆角），不要新做营销大卡。一行：品牌标（`AgentBrandIcon`）+ 主句 + 一行 mute 说明。按 main 探测露出，不编造：

| 条件 | 主句 | 说明 |
|---|---|---|
| 外置引擎已登录可对话 | 用 {引擎} 对话 | 走你已经登录的 {引擎}，不另存密钥 |
| 探测到 Ollama / LM Studio | 用本机模型 | 本机已在跑，不经过云 |
| 始终露出 | 添加 API 密钥 | 进现有官方预设表单（`#/settings/providers` 那套，见 `p0-add-provider-discover`）；保存后**回到本步**，该行改成「已连上」绿点 |
| 始终露出 | 以后再连 | 文本次级，不是红、不是禁用主路径 |

全新安装、什么都没探测到：只画「添加 API 密钥」和「以后再连」两行，**等权行**，不要把「添加 API 密钥」做成唯一主钮。多条路线同时在：推荐那条描 `accent` 细环，其余可点。

**引擎 ≠ 可以开始。** 现网 `ReadySummary` 写「{count} 个引擎就绪 · 浅/深 · 工作区」——引擎就绪不能当对话就绪。末屏 `ReadyMark` 绿勾只在有可对话路线时画；否则改成 mute 圆点，标题换成「还差一步：连一个模型」，摘要写「已装 N 个引擎 · 还没连模型」，主钮「去连接」，次钮「先逛逛」。有路线才保留「可以开始了」+「开始使用」。摘要里「工作区」改成「项目」。

**默认焦点。** 现网底栏「跳过设置」在 DOM 里先于主钮。本锁只钉：进窗首焦在胶囊主钮「开始」。向导 kbd / 昼夜开关皮 / 焦点环样式另开文案扫。

**介绍三卡。** `IntroPoints` 现网 `grid-cols-3` + `h-full` 拉满。本锁：卡**贴内容**，不要 `h-full`。第三张现网标题不在本锁用词范围，预览按现网铬中性画出，不钉死。

**外观强调色。** `THEME_ACCENTS` 现网英文被 `truncate` 切成 `Signal Bl…`。本锁走 i18n，中文短名：**信号蓝 / 终端绿 / Claude 琥珀 / 宇宙紫 / 石墨灰**。格子仍是五列色点+名，选中墨线环。名称是否再缩短交 jojo。

**设置 → 通用。** 复用 `SetupGuideReplay` + `SettingsCard` / `SettingsRow`。标题仍「启动引导」；按钮与行题改为「重新打开入门向导」。说明改成「再走一遍连模型、装引擎、外观和打开文件夹。」`settings-catalog-nav` 通用 `keywords` 补 `向导` / `入门` / `引导`。

**无项目空态（S1-5）。** 只在侧栏一个项目都没有时出现。说明在钮上面。钮是**中等主操作**，和侧栏「新对话」同级，不要满幅空白上的巨型蓝 CTA。用户亲手点「选择文件夹」可以弹系统选夹窗。侧栏「新对话」只 `navigate('#/')` 回到此空态。

**已有项目启动（S1-7）。** 启动后主区**直接进入该项目的会话面**，不要「打开工作区」，也不要「继续在 {项目} 里开始」中间页。上次用过的；没有记录就进第一个。亮/暗都验。反例：侧栏已有项目，主区仍满幅「打开工作区」。

**无密钥发送。** 改走 `ThreadNoticeBanner`（描边 `line`、非红）；密钥无效 / 网络失败 / 额度用完仍用红错误卡。界面不再出现「供应商密钥」。

**复用。** `SetupGuideDialog` / Header / Footer / `EngineInstallList` / `AppearanceChoice` / `WorkspaceChoice` `FolderDrop` / `ReadySummary` / `SetupGuideReplay` / `ThreadNoticeBanner` / `ThreadErrorBanner` / `ChatStage` + `EmptySessionStart` / 供应商预设表单。不新开第二套向导。

## BASE-P0-2 电脑操控在 Linux 上诚实

**一句话**：这台电脑能不能用电脑操控，用一句人话说清楚；不能用就不假装能用。

### Do
1. **可用性以 main 为真源**（执行器身份 / `desktop_doctor`），下发 renderer 四种状态：可用 / 需要授权 / 这台电脑暂不支持 / Beta 验证中。renderer 不自己判断。
   - **Beta**：有执行器但平台未经真机验收 → 开关可开，带黄色「Beta：这个平台还在验证中，可能不稳定。」只有「暂不支持」（无执行器）才禁用。
2. **不支持时**：开关不能打开（禁用），旁边写原因，如「这台电脑还不能用电脑操控：缺少操控组件。Linux 支持仍在验证中。」不再出现无解释的「无执行器」标签。
3. **入口跟着可用性走**：不可用时 composer 不出现「桌面」chip、`@桌面` / `@应用`；用户手写 `/computer-use` 时回一句人话说明当前不可用，不注册桌面工具。
4. **「检测权限」必有结果**：2 秒内给出通过或失败及原因；进行中有加载态。
5. **开关描述跟状态走**：开启时写开启后的效果，关闭时写关闭后的效果，不再开着却写「关闭时…」。
6. 「尚未在真机上验收」改为用户能懂的话：「Beta：这个平台还在验证中，可能不稳定。」
7. 与 §3.2e / CU-P0-A 对齐：未经真机 GUI 冒烟的平台不标「可用」。

### Don’t
- 没有执行器时开关保持开启
- 提供 `@桌面` 然后到执行时才失败
- 暴露内部名（`desktop_list_apps`、`desktop_*`、「同源」「插件店」等）
- renderer 自己写平台支持名单
- 为了「能用」放宽审批或绕过 doctor

### 验收 S2-1 … S2-6
| ID | 钉死句 |
|----|--------|
| S2-1 | Linux 无执行器：开关禁用并显示人话原因；不出现「无执行器」裸标签 |
| S2-2 | 同上：composer 无「桌面」chip，`@` 菜单无桌面/应用项；手写 `/computer-use` 得到不可用说明 |
| S2-3 | 「检测权限」2 秒内出结果（通过/失败+原因），点击有加载态 |
| S2-4 | 开关开/关时描述各自正确 |
| S2-5 | macOS 有执行器且已授权：开关可开、`@桌面` 出现，行为不回退 |
| S2-6 | 页面与 @ 菜单无内部工具名和开发备注 |

## Luna 视觉说明（P0-2）

**布局。** 不换设置页。仍是 `#/settings/computer-use`。四态画在**同一张主卡**里，层级固定：

1. **顶：状态 + 总开关** — 标题「电脑操控」+ 四态徽章 + 主 Switch + 跟态走的描述。
2. **中：检测权限 / 系统权限** — 次级行，不是等权大卡标题。
3. **底：高级（视觉降权）** — 小节头「高级」，收始终允许名单 + 高级坐标。深色里「高级」盒描边要比权限行更淡一档，但整卡外框仍看得见。

**四态铬（main 下发，renderer 不写死 darwin/linux）。**

| 态 | 徽章 | 开关 | 描述 |
|---|---|---|---|
| 可用 · 开 | 绿「可用」 | 可拨、开 | 本机看屏、点选、打字。 |
| 可用 · 关 | 绿「可用」 | 可拨、关 | 已关闭。普通发送不带桌面操控。 |
| 需要授权 | 黄「需要授权」 | 可拨 | 还差系统权限。下列三项 +「打开系统设置」。 |
| 这台电脑暂不支持 | mute「暂不支持」 | **禁用、保持关** | 这台电脑还不能用电脑操控：缺少操控组件。Linux 支持仍在验证中。权限行：「点『检测权限』可以看缺了什么。」 |
| Beta 验证中 | 黄「Beta 验证中」 | **可开**（有执行器、未经真机验收） | Beta：这个平台还在验证中，可能不稳定。权限行：「验证中。点『检测权限』查看结果。」 |

**不要**把「可用 · 开」写成「关掉时…」。反例必须画：开着却写「关闭时…」。C 端不出现 `desktop_*`、`executor_missing`、同源、插件店、**「医生」**。

**检测权限（S2-3）。** 加载态「正在检测权限…」；2 秒内换成两结果之一：**通过：三项权限已授权** / **失败：缺少操控组件** + 一行原因。不要无限转圈。

**需要授权。** 列出辅助功能 / 屏幕录制 / 输入监听三行，未授权的带「打开系统设置」。

**Composer / @。** 不可用则底栏无「桌面」芯片；`@` 无桌面/应用。网页一行若画，用中性「网页」，不要开发备注「本轮不做内置浏览器」。手写 `/computer-use` 回人话。

**macOS 已授权（S2-5）。** 开关开着 + 权限三行已授权 + Composer 底栏「桌面」芯片 + `@` 仍有桌面组。

**复用。** `ComputerUseSwitch` / `ComputerUseAccess` / `ComputerUseOperations` 降到「高级」/ `ComputerUseChip` / `mentions/desktop` / `ThreadNoticeBanner`。不新遥控器、不放宽审批、不绕过 doctor。

## BASE-P0-3 空对话

**一句话**：没说过话的对话不该留在列表里；用户能删掉不要的对话。

### Do
1. **草稿式新对话**：点「新对话」打开一个草稿视图；发出第一条消息（或加了第一个附件）才落库、才进侧栏和看板。离开未动过的草稿即丢弃。
2. **反复点「新对话」复用同一个未动草稿**，不叠加。
3. **回收存量空会话**：启动时清掉「零条用户消息、没打旗标、没改过工作流状态」的会话（本机）；有任何内容或用户标记的一律保留。fork、heartbeat、自动化会话不进回收名单，只按内容判断。
4. **看板「+ 新建」**：打开草稿（可选填标题），保存或发送后才出卡片；有取消。
5. **会话菜单加「删除」**：二次确认「删除这个对话？删除后无法恢复。」主按钮「删除」、次按钮「取消」；与「归档」并列且区分清楚。
6. 「…」菜单在所点行旁边弹出（顺带修位置）。

### Don’t
- 自动删除有消息或有用户标记的会话
- 删除不确认
- 影响会话 fork、heartbeat、自动化创建的会话（自动化运行生成的会话按内容判断，不按「是否用户手动发过」误删）
- 把会话数据上传云端

### 验收 S3-1 … S3-6
| ID | 钉死句 |
|----|--------|
| S3-1 | 连点 5 次「新对话」不发消息：侧栏与看板不新增任何会话 |
| S3-2 | 在草稿里发一条消息：会话出现在侧栏和看板「待办」 |
| S3-3 | 升级后首次启动：存量零消息、无标记的空会话消失；有内容/有旗标/改过状态的保留 |
| S3-4 | 看板「+ 新建」可取消；取消后不出卡片 |
| S3-5 | 会话菜单「删除」弹二次确认；确认后侧栏、最近、看板一起消失（若正在看则回草稿空态）；取消则不变 |
| S3-6 | 「…」菜单贴着所点行弹出 |

## Luna 视觉说明（P0-3）

**草稿视图。** 复用 `EmptySessionStart`。侧栏会话树**不出现**「新对话」行。第一条用户消息或第一个附件才 `createAndOpenSession`。连点「新对话」只聚焦同一草稿。

**看板。** 待办列底虚线草稿卡：可选标题、主钮「开始」、次钮「取消」。列名跟现网铬，不在本锁另钉用词。

**… 菜单。** `SessionRowMenu` 在归档下加分隔线再放「删除」（`text-danger`）。`align="end" side="bottom"` 贴该行。

**删除确认（S3-5）。** `ConfirmDialog`。钉锁文：「删除这个对话？删除后无法恢复。」确认后：侧栏、最近、看板一起消失；若正在看则回草稿空态。取消则不变。不要 `window.confirm`。

**回收。** 启动清「0 条用户消息 + 无旗标 + `workflowStatus` 空」。fork / heartbeat / 自动化不进回收名单，只按内容判断：助手已写出正文就留，即使用户一句没发。

**复用。** `EmptySessionStart` / `showEmptyHistoryChat` / `SidebarSessionRow` / `SessionRowMenu` / `KanbanColumn` / `ConfirmDialog`。不上云。
