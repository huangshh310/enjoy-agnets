# 本机 CLI × Enjoy 供应商：交互逻辑

> 背景长文，不是实现说明书。落地以 [`specs/agent-cli.md`](../specs/agent-cli.md)「当前真相」为准。  
> 对照：Cline（Provider 下拉 + Model 下拉）、OpenCode（`供应商/模型` 一次选）、CC Switch（按 App 切换、人多了分子菜单）。  
> 最后更新：2026-09-10

## 1. 用户要完成的一件事

**「这个助手聊天时用哪套账号、哪个模型。」**

不是「给每家 CLI 建一套供应商库」，也不是「先切模式再配档案」。

| 角色 | 页面 | 只做这件事 |
|---|---|---|
| 档案主人 | `#/settings/providers` | 创建 / 改 Key / 模型目录 / 看谁在用我 |
| 助手引用 | `#/settings/agent` 配置抽屉 | 选官方登录，或选一份**协议能对上**的档案 + 模型 |
| 开聊 | Composer 引擎胶囊 | 显示当前引用；不在这里 CRUD 供应商 |

Cursor / Grok / Antigravity / Amp **只吃官方登录**：列表仍有动力源列（`官方登录 · 已登录/未登录`），抽屉「这个助手用」是只读官方态 + 登录 CTA，**禁止假 vault 下拉**。OMP 共用同一个槽，文案是「OMP 供应商」，不是 Enjoy 档案库。

## 2. 从别人抄什么、不抄什么

| 来源 | 抄 | 不抄 |
|---|---|---|
| **Cline** | 永远是两个控件：供应商、模型。不把供应商铺成一列单选卡 | 按扩展自己的 API Provider 枚举；设置改了就全局生效 |
| **OpenCode** | 用户选的是「哪家的哪个模型」；档案在 Providers，选用在当前 Agent | 每项目一份 `opencode.json` 当唯一真相 |
| **CC Switch** | 当前来源必须一眼能读；供应商多了要筛选 / 分组；一份配置可套到多个 App | 每 App 独立供应商库、127.0.0.1 协议代理、改 `auth.json`、托盘一键接管所有 CLI |

Enjoy 不变量仍有效：一份 vault；开流默认注入子进程 env；写家目录必须用户点「同步到本机」；跨协议不可选。

## 3. 心智模型（三层，不要再加）

```
凭证来源          模型               作用范围
─────────         ────              ────────
官方登录     →    CLI 自己的目录     仅该助手 · Enjoy 内
vault 档案   →    该档案 models[]    默认可勾到其他兼容助手
                                      同步到本机 = 另一步
```

用户只回答三个问题，顺序固定：

1. **用官方账号，还是用设置里的某份档案？**
2. **（若档案）用哪个模型？**
3. **（可选）同样的档案要不要给 Codex / OpenCode / Gemini 也用？要不要写进系统终端？**

禁止把 3 提前到 1 前面。禁止没有档案就进入「已选 Enjoy」。

## 4. 界面结构（配置抽屉）

右侧抽屉，与知识库预览同一套壳。「这个助手用」永远在决策位（官方账号区之前）——**一个触发器，不是一列卡片**。绑了档案后，官方 inspect 不得再占英雄卡。

```
┌ 这个助手用 ──────────────────────────────────┐
│ [标] lucky0625 · hy3                     ▾  │  ← 当前值，一行
└─────────────────────────────────────────────┘
│ [◆] hy3                                  ▾  │  ← 仅选了档案才出现；行首族标
│ 也用于  [Codex ✓] [OpenCode] [Gemini]       │  ← 仅协议兼容的其他已装 CLI
│ 同时改本机终端配置 ▸                         │  ← 默认折叠
```

官方登录时，模型行仍用下面「执行源」里的 CLI 目录（inspect / catalog），不要复制第二份。

### 4.1 打开下拉

```
✓ 官方登录 · 已登录
───────────── 可用供应商 ─────────────
  grok          grok-4.6
  lucky0625     hy3
─────────────
+ 添加 OpenAI 供应商      ← 文案随该 CLI 的协议变
```

规则：

- **≥ 6 份**可用档案：顶部出现筛选框（CC Switch 托盘「防撑破」的桌面版）。
- **再多**：按协议分组（Anthropic / OpenAI / Gemini / DeepSeek），组内按名称。不按 CLI 分组——vault 只有一份。
- 当前项打勾。点官方登录 = 退回订阅，清 `providerId` 的「正在用」语义（`useCustomProvider=false`）。
- 「添加 {协议} 供应商」就地叠一层供应商抽屉（预填 preset），保存后**自动选中并用于这个助手**。不要 `navigate` 到供应商整页。
- 没有能用的档案：触发器停在官方登录；菜单里只有官方登录 + 添加。禁止虚线空态占半屏。

### 4.2 模型行

- 数据：绑定档案的 `models[]`，可手填 id。
- 图标：与 Composer 同一套 `cliModelFamilyKey` → `ModelBrandIcon`（Claude / GPT / Gemini / Grok / Kimi / GLM / MiniMax / DeepSeek…）。认不出族，回落该档案的 `ProviderIcon`，不要画 CLI 引擎标冒充模型。
- 模型很多：同一下拉可筛；不要为每个模型再占一张卡。

### 4.3 也用于其他助手

这是「别的 CLI 也要配」的正解：人还在这只抽屉里，不必每个助手走一遍。

- 列出 **已安装且协议兼容** 的其他 CLI（`providersCompatibleWith`）。
- 亮着 = 该 CLI 的 `useCustomProvider + providerId` 已指向这份档案。
- 点灭 = 那只 CLI 退回官方登录。
- 不列出 Cursor / Grok 等 `providerBind=none`。
- 不在这里写家目录。勾上只影响 Enjoy 内开流。

### 4.4 同步到本机（永远次级）

默认一行折叠文案。展开才有「同步 / 恢复备份」。  
说明必须是：Enjoy 里已经在用上面这份；这只改系统终端里的同名命令。  
Chat Completions → Codex 的限制只在同步前或模型行下用一句人话，不挡选档案。

## 5. 供应商页（反链，不是第二套配置）

Configured 列表：

- 无引用：不画「0 个智能体」。
- 有引用：芯片「Claude Code · Codex」，点到 `#/settings/agent?tool=` 闪卡。
- 编辑抽屉只读列出引用。
- 删除仍被引用：Confirm 列出助手名 → 解绑后退回官方登录。

添加 / 编辑档案本身也是右侧抽屉（四页签），不要居中 Dialog。

## 6. 关键路径

### 已登录 Claude，vault 里只有 OpenAI 中转

1. 打开 Claude 抽屉 → 当前是官方登录。
2. 下拉只有「官方登录」和「添加 Anthropic 供应商」。
3. 点添加 → 叠一层 Anthropic 表单（不是供应商列表页）。
4. 保存并用于这个助手 → 回到抽屉，当前值变成新档案 + 默认模型。
5. 需要的话再勾「也用于」里协议能吃 Anthropic 的助手（OpenCode），不要指望勾上 Codex。

### Codex 要用已有 lucky0625

1. 打开 Codex 抽屉 → 一行下拉，选 lucky0625。
2. 模型下拉带 Kimi / GLM / DeepSeek 族标。
3. 勾 OpenCode（若兼容）共用；Claude 不会出现在「也用于」。
4. 不点同步，终端里的 `codex` 仍是官方登录。

### 供应商有 20 份

下拉出现筛选；按协议分组。卡片网格和电台列表都禁止。

## 7. 文案（对人，不对协议栈）

| 位置 | 用 | 不用 |
|---|---|---|
| 区块标题 | 这个助手用 | 动力源模式 / 自定义端点注入 |
| 官方 | 官方登录 · 已登录 | OAuth / 订阅 / vault |
| 添加 | 添加 Anthropic 供应商 | 去添加 / 去模型供应商 |
| 空 | 菜单里只有官方 + 添加 | 「没有协议兼容且已保存密钥的档案」长空态 |
| 同步 | 同时改本机终端配置 | 同步到本机配置（易理解成聊天还不生效） |

## 8. 明确不做

- 每家 CLI 一份供应商 CRUD（CC Switch 产品线）。
- 本地 15721 协议翻译；Anthropic 档案不可出现在 Codex 下拉里。
- 给 Cursor / Grok 假 BYOK。
- 没有档案还把「使用 Enjoy 供应商」标成已选。
- 把 `oauth_token` / `custom endpoint` 当第一屏决策（账号区可保留，但「这个助手用」才是决策）。
- 选了 Enjoy 档案后仍把 `inspect.authAccount`（邮箱 / CUSTOM / 当前模型）画在抽屉顶部当当前供应商。官方登录在绑定后只作旁注「官方登录仍保留 · 仅系统终端」。

## 9. 对照现状的缺口

代码已有：一份 vault、协议过滤、开流注入、家目录同步、右侧抽屉、下拉选档案、模型族标、也用于其他助手、就地添加。

已对齐：本机 CLI 列表是密表三列（助手 | 动力源 | 操作）；Cursor/Grok 已装仍有动力源行。助手次行走版本 · 短路径；`homeSynced` 才画「已同步」；「官方仍保留」只进抽屉。动力源同构贴左，未找到 / 空档案为 `—`。列表无额度条、无「额度进配置」、无表底协议词。操作列定宽主槽 + 配置/复制。配置抽屉 380px 同壳，顶栏名称+配置提示+关闭。也用于圆片；同步带边框 details。添加收进下拉底部；≥6 筛选；多协议分组；胶囊正文仍是引擎 · 模型（绑定用 vault 所选，档案名进 title）；也用于短标签且不上沙箱；绑了档案后官方 inspect 降为旁注，「这个助手用」在账号区之前。仅官方 / OMP 共用该槽，不假 BYOK。绑了档案后 Composer / 发送不要求官方 OAuth（缺 Key 才 needs_key）。upsert/开流校验协议。自定义 ACP 也是右侧抽屉。对照预览：[`previews/local-cli-dense-p0.html`](../previews/local-cli-dense-p0.html)。`dense-v2` 是过程稿 stub。
